<div class="px">
<header class="hero">
<div class="kicker">Data structures: the priority queue, with no pointers at all</div>
<p class="lede">A heap is a binary tree with one promise: every parent is smaller than its children (in a <strong>min-heap</strong>), so the minimum always sits at the root, ready in O(1). The surprise is that the tree is never actually built — no nodes, no pointers. A heap is an ordinary <strong>array</strong>, and the tree exists only in the arithmetic of the indices: multiply or divide by two with a binary shift and you walk from any element to its parent or children. This page builds that idea up piece by piece, then runs the three operations that maintain it — heapify, insert, and extract-min — live, step by step.</p>
<div class="keybox"><p><strong>The one-sentence idea.</strong> Store a complete binary tree level by level in an array. Because the tree is complete, the children of index <em>i</em> are always at <em>2i + 1</em> and <em>2i + 2</em> and the parent is one right-shift away — so “rebalancing” is just swapping an element up or down a single root-to-leaf path, never touching the rest of the array.</p></div>
</header>
</div>

## 1 — What a heap is: a complete tree with one ordering rule

<div class="px">
<p>Two properties define a binary heap, and they are independent. <strong>Shape:</strong> the tree is <em>complete</em> — every level is fully filled except possibly the last, which fills left to right with no gaps. <strong>Order (min-heap):</strong> every parent is less than or equal to both of its children. Note what the order property does <em>not</em> say: nothing relates a node to its siblings, its cousins, or its grandchildren beyond the chain of parents. A heap is only <em>partially</em> ordered — it is not sorted, and it is not a binary search tree. That weakness is exactly what makes it cheap to maintain.</p>

## 2 — The array embedding: parents and children by binary shift

<div class="px">
<p>Number the tree positions in level order starting at 0, and store position <em>i</em> at <code>A[i]</code>. Then the family of any node is pure arithmetic. Doubling an index moves one level down, halving moves one level up — and doubling and halving integers is precisely what the binary shift operators do: <code>&lt;&lt; 1</code> appends a 0 bit (×2), <code>&gt;&gt; 1</code> drops the last bit (⌊÷2⌋). In the cleaner 1-indexed convention (root at <code>A[1]</code>, slot 0 wasted) the formulas are exact shifts with no corrections: parent is <code>i &gt;&gt; 1</code>, children are <code>i &lt;&lt; 1</code> and <code>(i &lt;&lt; 1) + 1</code>. With the usual 0-indexed array the same shifts appear with +1 and −1 adjustments, shown in the table.</p>

## 3 — The midpoint: where the parents end and the leaves begin

<div class="px">

## 4 — Heapify: building a heap in place, from the midpoint down

<div class="px">
<p>Given an arbitrary array, the naive build inserts elements one at a time: O(n log n). Floyd's heapify is smarter and does it <em>in place</em>, in O(n). The idea follows directly from Step 3: leaves are already heaps, so start at the midpoint — the last parent — and work <em>backwards</em> to the root, <strong>sifting down</strong> each element: compare it with its smaller child and swap if the child is smaller, then keep sifting from the child's position until the element is no larger than both children, or reaches a leaf. Going bottom-up guarantees that when index <em>i</em> is processed, both of its subtrees are already valid heaps, so one sift-down makes the whole subtree rooted at <em>i</em> valid. When the root finishes, the array is a heap.</p>

## 5 — Insert: append at the end, then sift up

<div class="px">
<p>Adding an element must preserve completeness, and there is exactly one slot that does: the next free position at the end of the array, <code>A[n]</code>, the leftmost gap on the last level. Placed there, the new element can break the order property in only one way: it may be smaller than its parent. So <strong>sift up</strong>: while the element is smaller than its parent (found with one right shift, <code>(i − 1) ≫ 1</code>), swap them, and repeat from the parent's position. The element climbs at most one root-to-leaf path, so insert is O(log n), and the rest of the heap is never touched. This is precisely a targeted rebalance: the damage from an insertion is confined to a single path, and sift-up is the repair walk along it.</p>
<pre class="code">push(A, x):  <span class="cm">// O(log n)</span>&#10;&nbsp;&nbsp;A.append(x)&#10;&nbsp;&nbsp;i = A.length - 1&#10;&nbsp;&nbsp;<span class="cm">// sift up, parent(i) = (i - 1) &gt;&gt; 1</span>&#10;&nbsp;&nbsp;while i &gt; 0 and A[parent(i)] &gt; A[i]:&#10;&nbsp;&nbsp;&nbsp;&nbsp;swap A[i], A[parent(i)]&#10;&nbsp;&nbsp;&nbsp;&nbsp;i = parent(i)</pre>

## 6 — Extract-min: take the root, move the last element up, sift down

<div class="px">
<p>Reading the minimum is O(1): it is <code>A[0]</code>. Removing it is the interesting part. Deleting the root outright would split the tree, so instead: save <code>A[0]</code>, move the <em>last</em> element <code>A[n − 1]</code> into the root slot, shrink the heap by one, and repair. The moved element is almost surely too big for the root, but it can only violate order against its children — so <strong>sift down</strong>, exactly the repair used by heapify: swap with the <em>smaller</em> child (choosing the smaller child is essential — swapping with the larger one would put that larger child above the smaller one and break their order), repeating until the element settles. One path down, O(log n), and the heap is whole again with the new minimum at the root.</p>
<pre class="code">popMin(A):  <span class="cm">// O(log n)</span>&#10;&nbsp;&nbsp;top = A[0]&#10;&nbsp;&nbsp;<span class="cm">// last element moves to the root</span>&#10;&nbsp;&nbsp;A[0] = A.pop()&#10;&nbsp;&nbsp;if A not empty:&#10;&nbsp;&nbsp;&nbsp;&nbsp;siftDown(A, A.length, 0)&#10;&nbsp;&nbsp;return top</pre>

## 7 — Rebalancing: when it is needed, and why it is always one path

<div class="px">
<p>A heap never needs the global rebalancing a search tree does — there is no rotation, no re-coloring, no restructuring pass. The order property can only break <em>locally</em>, along the single path touched by a change, and each operation repairs exactly that path. The complete list of triggers:</p>
<table class="data">
<tr><th style="width:26%">What changed</th><th style="width:30%">What can break</th><th>Repair</th></tr>
<tr><td>Element appended (insert)</td><td>New element may be smaller than its parent</td><td><strong>Sift up</strong> from the last index: swap with parent while smaller</td></tr>
<tr><td>Root removed (extract-min)</td><td>Last element, moved to the root, may be larger than a child</td><td><strong>Sift down</strong> from index 0: swap with the smaller child while larger</td></tr>
<tr><td>A key <em>decreases</em> (priority raised)</td><td>Element may now be smaller than its parent</td><td><strong>Sift up</strong> from that index: the core of Dijkstra's decrease-key</td></tr>
<tr><td>A key <em>increases</em> (priority lowered)</td><td>Element may now be larger than a child</td><td><strong>Sift down</strong> from that index</td></tr>
<tr><td>Arbitrary array, or many keys changed</td><td>Order may be violated everywhere</td><td><strong>Heapify</strong> from the midpoint: rebuild in O(n) rather than repairing pair by pair</td></tr>
</table>
<p>The direction rule is the whole decision procedure: an element that got <em>smaller</em> (or arrived from below) can only be wrong against its parent, so it can only need to go <em>up</em>; an element that got <em>larger</em> (or arrived from above) can only be wrong against its children, so it can only need to go <em>down</em>. Try all of it in the playground: insert and extract animate their repair paths, decreasing or increasing a selected element triggers the matching sift, and “Shuffle” breaks the heap so you can watch heapify restore it from the midpoint.</p>

<h3>The one caveat: arbitrary deletion and decrease-key need a map</h3>
<ul>
<li>Sift-up after a key change is O(log n) <em>if you know the index</em>. Finding an arbitrary element in a heap is O(n) (heaps are not searchable), so real priority queues keep a side table from element to current index and update it on every swap.</li>
<li>Deleting an arbitrary element combines both repairs: overwrite it with the last element, then sift up <em>or</em> down depending on how the replacement compares with its new parent and children.</li>
</ul></div>

## 8 — Costs at a glance, and where heaps earn their keep

<div class="px">
<table class="data">
<tr><th>Operation</th><th>Cost</th><th>Why</th></tr>
<tr><td>Peek minimum, <code>A[0]</code></td><td>O(1)</td><td>The minimum is the root by definition</td></tr>
<tr><td>Insert (push)</td><td>O(log n)</td><td>Append, then sift up one path of height ⌊log₂ n⌋</td></tr>
<tr><td>Extract-min (pop)</td><td>O(log n)</td><td>Move last to root, sift down one path</td></tr>
<tr><td>Decrease / increase key</td><td>O(log n)</td><td>One sift, up or down, from the element's index</td></tr>
<tr><td>Build (heapify)</td><td>O(n)</td><td>Bottom-up sift-downs from the midpoint; most paths are short</td></tr>
<tr><td>Search for a value</td><td>O(n)</td><td>No ordering between subtrees to prune by — the heap's one real weakness</td></tr>
<tr><td>Extra memory</td><td>O(1)</td><td>In place in the array; no pointers, no node objects</td></tr>
</table>
<p>That cost profile — cheapest possible access to the extremum, logarithmic updates, linear build, zero overhead — makes the heap the default engine wherever work is consumed in priority order: operating-system and event-loop schedulers, Dijkstra's and A* shortest paths (with decrease-key), Huffman coding, streaming medians with paired min- and max-heaps, top-k queries, and heapsort, which is just heapify followed by n extract-mins for an O(n log n) sort with O(1) extra space. Whenever a problem asks for “the smallest (or largest) thing, repeatedly, while new things keep arriving”, it is asking for a heap — and underneath, it is asking for an array, two shifts, and a midpoint.</p>

function buildHeapifySteps(start){
  var a = start.slice(), n = a.length, m = (n >> 1) - 1;
  var steps = [{arr: a.slice(), hl: (function(){ var h = {}; h[m] = "mid"; return h; })(),
    msg: "Start: [" + a.join(", ") + "], n = " + n + ". The midpoint is (" + n + " ≫ 1) − 1 = " + m + " (gold). The scan runs from index " + m + " down to 0; indices above " + m + " are leaves and already valid one-element heaps."}];
  for(var i = m; i >= 0; i--){
    var cur = i;
    var first = true;
    while(true){
      var l = left(cur), r = right(cur), smallest = cur;
      if(l < n && a[l] < a[smallest]) smallest = l;
      if(r < n && a[r] < a[smallest]) smallest = r;
      if(smallest === cur){
        var h1 = {}; h1[cur] = "cur"; if(l < n) h1[l] = "kid"; if(r < n) h1[r] = "kid";
        steps.push({arr: a.slice(), hl: h1, msg: (first ? "Sift down from index " + i + " (value " + a[cur] + "): " : "Now at index " + cur + " (value " + a[cur] + "): ") + "it is no larger than " + (l < n ? "its children (" + a[l] + (r < n ? " and " + a[r] : "") + ")" : "anything — it is a leaf") + ", so it stays. Subtree rooted at " + i + " is now a valid heap."});
        break;
      }
      var h2 = {}; h2[cur] = "cur"; h2[smallest] = "kid";
      var before = a[cur], childVal = a[smallest];
      steps.push({arr: a.slice(), hl: h2, msg: "Sift down from index " + cur + ": value " + before + " is larger than its " + (smallest === l ? "left" : "right") + " child " + childVal + " at index " + smallest + ": swap them."});
      var t = a[cur]; a[cur] = a[smallest]; a[smallest] = t;
      cur = smallest; first = false;
    }
  }
  var done = {}; for(var k = 0; k < n; k++) done[k] = "done";
  steps.push({arr: a.slice(), hl: done, msg: "Done: [" + a.join(", ") + "] is a valid min-heap — every parent is no larger than its children, and the minimum " + a[0] + " is at the root. The array was rearranged in place; no second array was used."});
  return steps;
}

function buildInsertSteps(heap, v){
  var a = heap.slice();
  var steps = [{arr: a.slice(), hl: {}, ghost: v, msg: "Ready to insert " + v + " into the heap [" + a.join(", ") + "]. It must go in the next free slot, index " + a.length + ", to keep the tree complete."}];
  a.push(v);
  var i = a.length - 1;
  var hl0 = {}; hl0[i] = "cur";
  steps.push({arr: a.slice(), hl: hl0, msg: "Placed " + v + " at index " + i + ". Now check the parent at index " + parent(i) + " and sift up while the parent is larger."});
  while(i > 0){
    var p = parent(i);
    var hl = {}; hl[i] = "cur"; hl[p] = "par";
    if(a[p] > a[i]){
      steps.push({arr: a.slice(), hl: hl, msg: "Parent A[" + p + "] = " + a[p] + " is larger than " + a[i] + ": swap. The element climbs to index " + p + "."});
      var t = a[i]; a[i] = a[p]; a[p] = t; i = p;
    } else {
      steps.push({arr: a.slice(), hl: hl, msg: "Parent A[" + p + "] = " + a[p] + " is no larger than " + a[i] + ": the order property holds here, so sift-up stops at index " + i + "."});
      break;
    }
  }
  if(i === 0){
    var hlR = {}; hlR[0] = "cur";
    steps.push({arr: a.slice(), hl: hlR, msg: v + " has climbed all the way to the root — it is the new minimum. Final heap: [" + a.join(", ") + "]."});
  }
  var done = {}; for(var k = 0; k < a.length; k++) done[k] = "done";
  steps.push({arr: a.slice(), hl: done, msg: "Done: [" + a.join(", ") + "] is a valid min-heap with " + a.length + " elements. Only the path from the old last slot to index " + i + " was touched."});
  return steps;
}

function buildExtractSteps(heap){
  var a = heap.slice(), n = a.length;
  var steps = [], total = n;
  var top = a[0];
  steps.push({arr: a.slice(), hl: {0: "cur"}, total: total, msg: "The minimum is the root: A[0] = " + top + ". It will be removed; the last element, A[" + (n - 1) + "] = " + a[n - 1] + ", will move into its place."});
  var last = a.pop();
  if(a.length === 0){
    steps.push({arr: [], hl: {}, total: total, msg: "That was the only element — the heap is now empty."});
    return {steps: steps, extracted: top, result: []};
  }
  a[0] = last;
  steps.push({arr: a.slice(), hl: {0: "cur"}, total: total, msg: "Moved " + last + " to the root and shrank the heap to " + a.length + " elements (the greyed cell is out). " + last + " is larger than a child, so sift down to repair."});
  var cur = 0;
  while(true){
    var l = left(cur), r = right(cur), smallest = cur;
    if(l < a.length && a[l] < a[smallest]) smallest = l;
    if(r < a.length && a[r] < a[smallest]) smallest = r;
    if(smallest === cur){
      var h = {}; h[cur] = "cur"; if(l < a.length) h[l] = "kid"; if(r < a.length) h[r] = "kid";
      steps.push({arr: a.slice(), hl: h, total: total, msg: "At index " + cur + ", " + a[cur] + " is no larger than its children — sift-down stops. The heap is valid again."});
      break;
    }
    var h2 = {}; h2[cur] = "cur"; h2[smallest] = "kid";
    steps.push({arr: a.slice(), hl: h2, total: total, msg: "At index " + cur + ": " + a[cur] + " is larger than its smaller child " + a[smallest] + " at index " + smallest + ": swap, and keep sifting from index " + smallest + "."});
    var t = a[cur]; a[cur] = a[smallest]; a[smallest] = t; cur = smallest;
  }
  var done = {}; for(var k = 0; k < a.length; k++) done[k] = "done";
  steps.push({arr: a.slice(), hl: done, total: total, msg: "Done: extracted " + top + ". The remaining heap is [" + a.join(", ") + "] and the new minimum, " + a[0] + ", is at the root."});
  return {steps: steps, extracted: top, result: a.slice()};
}
